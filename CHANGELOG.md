## v0.5.57 — Release notes and project handoff pipeline

Adds a structured release metadata pipeline that generates GitHub release notes, in-app patch notes, a cumulative changelog, and a durable project handoff document for future development sessions.

### What's changed

- Added release_notes/releases.json as the single source of truth for release summaries and engineering handoff context.
- Added release_tools/generate_release_notes.py to generate GitHub release bodies, CHANGELOG.md, and PROJECT_STATE.md deterministically.
- The Updates page now displays patch notes returned in the existing GitHub release manifest.
- Prerelease publication uses the generated release body instead of a hard-coded release description.

### Technical notes

- CI validates that CHANGELOG.md and PROJECT_STATE.md match the structured release metadata before publication.
- Release metadata contains user-facing notes and separate engineering fields so future sessions can recover project state without relying on conversation history.

### Validation

- The generator validates semantic versions, duplicate versions, required release summaries, and next-step structure.
- JavaScript syntax checks cover the patch-note renderer, which renders release Markdown through text nodes rather than injecting release HTML.

## v0.5.56 — Serialized configuration mutations

Prevented lost configuration updates by moving application-generated configuration mutations onto a serialized read-modify-write transaction path.

### What's changed

- Added torrent_dashboard/config_store.py with a shared reentrant lock.
- Configuration mutations now reload the latest config while holding the lock, apply the requested transformation, atomically replace config.json, and release the lock only after the write completes.
- Profile, password, avatar, user, integration, settings, update-source, notification-sound, setup, and CLI password writes use the transaction path.

### Fixes

- Concurrent dashboard configuration writes can no longer silently overwrite unrelated changes made by another request.

### Technical notes

- First-run setup rechecks setup completion inside the transaction to prevent duplicate concurrent setup commits.
- Development and prerelease publication were separated into dedicated branches so intermediate commits are not exposed through the updater.

### Validation

- Added concurrent mutation regression tests that verify two simultaneous changes both survive.
- Added failed-mutation coverage to verify exceptions do not persist partial state.

### Known issues

- The transaction lock protects writes made by the running Torrent Dashboard process; it does not coordinate an external editor modifying config.json at the same instant.

## v0.5.55 — User and account backend modularization

Started the backend modularization by extracting the user and account domain from dashboard.py into torrent_dashboard/users.py without intentional behavior changes.

### What's changed

- Moved password hashing and verification, user normalization, profile editing, avatar handling, password changes, role helpers, and user CRUD into torrent_dashboard/users.py.
- Preserved the existing dashboard.py call surface by importing and re-exporting the extracted helpers.

### Technical notes

- Established torrent_dashboard as the package boundary for subsequent backend extraction work.

### Validation

- Python compilation and release source validation passed before the prerelease was published.
