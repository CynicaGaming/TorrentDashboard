# Notifications and Integration Health

## Browser and mobile notifications

Torrent Dashboard can show notifications through the browser or installed PWA. The Notifications settings provide controls to enable, disable, and test this path.

Enabling notifications requests permission from the browser/device and saves only the browser-notification setting. Disabling notifications in Torrent Dashboard stops the application from using that notification path, but it does not revoke permission at the operating-system or browser level.

On supported Apple mobile devices, browser notifications require the site to be installed to the Home Screen as a PWA before permission can be granted.

### Background Web Push boundary

The service worker can display notifications and contains a Web Push event handler, but the current application does not register and persist `PushManager` subscriptions or operate a server-side Web Push sender. As a result, the notification controls should be understood as browser/PWA device notifications generated by the dashboard, not as a complete independent push-delivery service to a closed application.

A future background Web Push implementation would need subscription lifecycle management, VAPID/application-server keys, secure subscription storage, expiration cleanup, and server-side delivery/error handling.

## Completion sounds

Torrent Dashboard supports a default sound and a user-uploaded custom sound.

The current default sound is the requested `notification-default.mp3`. Its expected properties are:

- decoded size: 40,704 bytes;
- SHA-256: `5be19a030c39e9fef9084d247e1bda23cb947e9e430abfc2e97376e04ff868b3`.

The source repository stores the MP3 as seven Base64 text parts. The service worker decodes and caches the MP3 once during installation. `release_tools/validate_checkpoint.py` reconstructs those parts independently and rejects a release if the size, MP3 signature, or digest changes unexpectedly.

The previous `default-completion.wav` remains in the repository as a compatibility asset. A small browser shim maps the old default path to the MP3. Custom sounds are not redirected.

Custom notification sounds may be WAV, MP3, or OGG files up to the application limit and are stored under the runtime `data/` directory rather than committed to the repository.

## External notification integrations

Completion events can also be delivered by configured external integrations. These are server-side and independent of browser notification permission.

Delivery-capable integrations include Discord, ntfy, generic webhooks, and Home Assistant. Other integrations are used primarily for media-service status and torrent matching.

## Integration health indicator

The Integrations settings page shows a status dot to the left of each integration name:

- **Green — Connected:** the most recent explicit connection test succeeded.
- **Yellow — Needs attention:** the integration is configured but has not been tested on this browser, settings changed after the last test, or the test returned an application/authentication/configuration problem rather than a network disconnect.
- **Red — Disconnected:** the integration is disabled or the most recent test indicated a network-level reachability failure such as DNS, refusal, or timeout.

The last explicit health result is stored locally in the browser so the indicator remains useful between page visits. It is a UI health hint, not a server-side monitoring system.

### Why tests are not automatic

Some connection tests have side effects. Testing Discord, ntfy, a generic webhook, or Home Assistant sends a real test message to that destination. Torrent Dashboard therefore does not probe every integration automatically when the page opens.

After editing an integration, the indicator returns to yellow until the integration is tested again. This avoids showing a stale green state after configuration changes.

## Troubleshooting

If a browser/PWA test fails:

1. Confirm notification permission is allowed for the dashboard origin.
2. On Apple mobile, confirm the dashboard is installed to the Home Screen and opened from the installed PWA.
3. Confirm the dashboard is being served from an origin where the browser allows notification APIs.
4. Reload once after a service-worker update so the new worker controls the page.

If an integration is yellow or red, expand it and use **Test Connection**. For delivery integrations, expect a real test message when the test succeeds.
